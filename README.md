# CLI MCP Agent: weather + local time

Полноценный агент для Track A:
- принимает запрос пользователя в CLI
- сам решает, когда вызывать инструменты
- использует **2 MCP-сервера**
- формирует ответ на основе внешних API.

## Архитектура

- `main.py` — CLI-агент (MCP-клиент), который по очереди вызывает инструменты
- `mcp_servers/weather_server.py` — MCP-сервер с функцией `get_weather(city)`
- `mcp_servers/time_server.py` — MCP-сервер с функцией `get_local_time(timezone)`
- `logs/tool_trace.jsonl` — лог вызовов инструментов (`started` / `finished`)
- `REFLECTION.md` — честная рефлексия по моему решению.

## Какие API используются

- Open-Meteo Geocoding API: поиск города и координат/таймзоны
- Open-Meteo Forecast API: текущая температура, ветер, осадки
- TimeAPI.io: локальное время по таймзоне

## Почему это соответствует Track A

- Есть внешние API как инструменты (2 API)
- Есть логика агента: в `main.py` он решает, вызывать инструменты или нет
- Есть реальное использование инструментов через MCP: 2 MCP-сервера вызываются в одном сценарии
- Ответ формируется по данным внешних API

## Фишка проекта

Ключевая фишка — не просто показать цифры погоды, а сразу подсказать, что делать:

- агент дает совет по одежде;
- агент отдельно подсказывает, брать ли зонт;
- пользователь получает готовое решение, а не только цифры.

Это делает MVP практичным: перед выходом из дома не нужно самому разбирать температуру, ветер и осадки. Что очень удобно, ведь перед выходом на улицу выглянешь в окно, а там кто-то в пуховике,а кто-то в одной футболке...

## Установка

```bash
pip install -r requirements.txt
```

## Запуск (одна команда)

```bash
python main.py "погода в Москве"
```

## Примеры запросов

```bash
python main.py "погода в Москве"
python main.py "будет ли дождь в Санкт-Петербурге"
python main.py "какой ветер в Минске"
python main.py "расскажи анекдот"
```

Ожидаемое поведение:
- для погодного запроса агент вызывает оба MCP-сервера и возвращает:
  - погоду,
  - локальное время,
  - совет по одежде и зонту;
- если город не указан:
  - `Укажите город, например: "погода в Москве".`
- если город не найден:
  - `Не удалось найти такой город. Уточните название...`
- для непогодного запроса возвращает:
  - `Не умею, спроси про погоду.`


## Я выбрала Track A, потому что это штука, которую я сама бы реально использовала. Когда собираешься выходить, не хочется открывать несколько приложений и самой разбираться в цифрах. Хочется быстро понять: холодно или нет, нужен ли зонт, и что вообще надеть. Поэтому я делала не просто “учебный проект”, а маленький рабочий инструмент под обычную бытовую ситуацию. По этой же причине выбрала CLI: одна команда, быстрый ответ, никакого лишнего интерфейса.
